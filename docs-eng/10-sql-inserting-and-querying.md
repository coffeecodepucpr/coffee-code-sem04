## // Before you start

In Module 09 you created the five tables, but they are empty. This module teaches you how to put data in them (`insert`), how to read what was stored (`select`) and how to fix or delete rows (`update` and `delete`). It is the SQL equivalent of everything you did with arrays in Week 03.

## // The problem: empty tables answer nothing

Week 03's `gruposMock` had six ready-made groups. For the database to have the same content, each object in the array needs to become rows in tables. And then you need a way to ask the database "which groups have more than six spots?", which is what `.filter()` did in JavaScript.

## // `insert`: storing rows

```sql
insert into materias (nome, codigo)
values ('Cálculo I', 'MAT101');
```

The list in parentheses after the table name says **which columns** you will fill in, and `values` brings the values, in the same order. The columns left out (like `materia_id`, generated by `identity`) get their default value.

To store several rows at once, separate the sets of values with commas:

```sql
insert into materias (nome, codigo) values
  ('Estrutura de Dados', 'INF201'),
  ('Banco de Dados',     'INF301');
```

As you saw in Module 09, order matters: tables referenced by foreign keys get data first. In the project, `materias` and `usuarios` before `grupos`, and `grupos` and `usuarios` before `participacoes`.

## // From `gruposMock` to the tables

Each object in the array unfolds into rows in more than one table:

| In `gruposMock` (Week 03) | In the database |
|---|---|
| `materia: "Cálculo I"` | One row in `materias`, and its `materia_id` in `grupos` |
| The group name | The `nome_grupo` column in `grupos` |
| `participantes: 5` | **Disappears**: becomes five rows in `participacoes` |
| `horario: "encontros às terças"` | One row in `encontros` (day of the week, time and location) |

The file `docs/example/sql/02-seed.sql` already does this conversion for the example's six groups. In it, the subject ids are written directly (1, 2, 3...), because the database was just created and the order is known. In a database with real data, the safest approach is to look up the id with a subquery, instead of typing it by hand:

```sql
insert into grupos (nome_grupo, materia_id, max_participantes)
values (
  'Cálculo II na prática',
  (select materia_id from materias where nome = 'Cálculo I'),
  5
);
```

## // `returning`: getting back what was stored

PostgreSQL lets you ask for the values of the newly created row, including the id the database generated:

```sql
insert into grupos (nome_grupo, materia_id) values ('Teste', 1)
returning grupo_id, nome_grupo;
```

This avoids having to run a second query just to find out the new row's id.

## // `select`: reading the data

```sql
select * from materias;
```

```
 materia_id |          nome          | codigo
------------+------------------------+--------
          1 | Cálculo I              | MAT101
          2 | Estrutura de Dados     | INF201
          3 | Banco de Dados         | INF301
          4 | Engenharia de Software | INF305
          5 | Redes de Computadores  | INF310
          6 | Sistemas Operacionais  | INF315
```

The `*` means "all columns". To choose only the ones you care about, list them:

```sql
select nome_grupo, max_participantes from grupos;
```

### > Filtering with `where`

```sql
select nome_grupo, max_participantes
from grupos
where max_participantes >= 6
order by nome_grupo;
```

```
       nome_grupo       | max_participantes
------------------------+-------------------
 Cálculo passo a passo  |                 6
 Modelagem e SQL        |                 8
 Redes na unha          |                 6
```

The most used operators in `where`:

| Operator | Use | Example |
|---|---|---|
| `=`, `<>`, `<`, `>`, `<=`, `>=` | Compare values | `max_participantes >= 6` |
| `and`, `or`, `not` | Combine conditions | `materia_id = 1 and max_participantes > 4` |
| `in (...)` | One of several values | `materia_id in (1, 3)` |
| `ilike` | Similar text, case-insensitive | `nome_grupo ilike '%sql%'` |
| `is null` | The column is empty | `descricao is null` |

In `ilike`, the `%` symbol means "any sequence of characters". That is why `'%sql%'` finds the group "Modelagem e SQL". It is the database equivalent of the `.includes()` the Dashboard search used in Week 03.

### > Sorting and limiting

```sql
select nome_grupo, max_participantes
from grupos
order by max_participantes desc, nome_grupo
limit 3;
```

`order by` sorts (`desc` reverses the order), and `limit` returns only the first rows.

## // `update` and `delete`: fixing and deleting

```sql
update grupos
set max_participantes = 12
where nome_grupo = 'Modelagem e SQL';
```

```sql
delete from participacoes
where usuario_id = 1 and grupo_id = 2;
```

The second command is, in SQL, the "Leave group" from the Week 03 Profile: it removes the row that links the person to the group, and nothing else.

> **THE DANGER OF A FORGOTTEN `WHERE`**
> `update` and `delete` without `where` affect **all** rows in the table. `delete from participacoes;` deletes everyone's memberships, without asking for confirmation. The habit that avoids the scare: first write a `select` with the same `where`, check which rows show up, and only then swap the `select` for `update` or `delete`.

Two PostgreSQL helpers to rehearse without risk: `returning` also works in `update` and `delete`, showing the affected rows, and you can wrap the command in `begin;` and end with `rollback;` to undo everything.

## // What `.filter()`, `.find()` and friends become in SQL

| JavaScript (Week 03) | SQL |
|---|---|
| `lista.filter(...)` | `select ... where ...` |
| `lista.find(...)` | `select ... where ... limit 1` |
| `lista.push(item)` | `insert into ...` |
| `lista.filter(g => g.id !== id)` (remove) | `delete from ... where ...` |
| Changing a property of an object | `update ... set ... where ...` |
| `lista.sort(...)` | `order by ...` |

## // Good example × bad example

**Bad example**: an `update` without `where`:

```sql
update grupos set max_participantes = 12;
```

All six groups now have a limit of 12 participants.

**Good example**: the same `update`, restricted to the right row:

```sql
update grupos set max_participantes = 12
where nome_grupo = 'Modelagem e SQL';
```

Only one group changes, and the command reports `UPDATE 1`, confirming that a single row was affected.

## // Common mistakes

| Mistake | Why it happens | How to fix it |
|---|---|---|
| `violates foreign key constraint` when inserting | The referenced row does not exist yet | Insert into the referenced table first |
| `duplicate key value violates unique constraint "participacoes_pkey"` | The person is already in that group | Check what already exists before inserting |
| Forgetting `where` in an `update` or `delete` | The command works anyway | Test with `select` first, and use `begin` and `rollback` to rehearse |
| Comparing text with double quotes (`"Cálculo I"`) | In JavaScript both kinds of quotes work | In SQL, text uses single quotes: `'Cálculo I'` |
| Forgetting `%` in `ilike` | Without it, the pattern requires an exact match | Use `'%term%'` to search for a piece of the text |
